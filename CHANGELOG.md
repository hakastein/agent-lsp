# Changelog

## v0.6.1

- Go: на windows ответы не зависят от рабочего каталога процесса. `go.work` или `go.mod` в рабочем каталоге на диске
  корня (выше корня таких файлов нет) gopls принимал за файл корня: зависимость из `vendor/` или каталога `replace` не
  разрешалась, `Definition` отвечал пустым ответом, `References` — ошибкой.
- CI гоняет `make go` на ubuntu, macos и windows.

## v0.6.0

- Go: `Index.Origin(path)` — происхождение файла по правилу `Origin` объявления: корень (в том числе модуль, который
  `go.work` корня подключает из каталога вне корня), vendor-каталог корня, стандартная библиотека или зависимость.
  Файл может не существовать.

## v0.5.1

- Go: файл с синтаксической ошибкой не роняет процесс. `Outline`, `Symbols` и `Definition` отвечают тем, что
  восстановил парсер; объявление, которое файл обрывает (например, `func f( {` в конце файла), кончается концом файла.
- Go: модуль, который `go.work` корня подключает из каталога вне корня (`use ../lib`), — часть корня: позиция в его
  файлах — вопрос для `Definition`, `References` и `Rename`, `Outline` читает его файлы, его объявления — с `Origin`
  корня, и `Rename` их переименовывает. Каталог из `replace` остаётся зависимостью (`module`).

## v0.5.0

- Go: `Rename` — правки, которые переименовывают символ в пакетах корня под linux, darwin и windows, в том числе в
  файлах только одной из них. Сам ничего не пишет. Правку, которую делают несколько платформ, ответ содержит один
  раз. Правки идут по файлам, строкам и колонкам и включают имя в докблоках. `Unresolved` пуст.
- Go: переименование метода интерфейса переименовывает, как gopls, методы типов, которые код присваивает интерфейсу;
  тип, который интерфейс реализует, но интерфейсу не присвоен, свой метод сохраняет.
- Go: отказ `Rename` с местом: новое имя конфликтует с другим символом (места из проверки gopls, с полными путями);
  объявление вне корня — в стандартной библиотеке, зависимости или vendor (место объявления); метод типа, который
  код присваивает интерфейсу переименуемого метода, объявлен в пакете, куда переименование не доходит (`time.Time`,
  присвоенный интерфейсу корня; место метода); поле или метод типа без имени на уровне пакета, если вопрос в файле,
  который собирают не все платформы (место вопроса); метод конкретного типа `String() string`, `Error() string` или
  `Format(fmt.State, rune)`, который `fmt` находит через `any` (место метода). Переименование пакета
  (объявление `package` или имя импорта) — `agentlsp.ErrNotSupported`. Место без символа — пустой ответ.
- Go: символ, объявленный для платформ по отдельности (`f` в `f_unix.go` и в `f_windows.go`, метод или поле такого
  типа), — один символ: `References` с любого объявления находит использования всех, `Rename` переименовывает все.
  Платформа, которая не собирает файл вопроса, ищет символ по пакету, типу, в котором он объявлен, и имени.
- Форк gopls: `golang/rename.go` и `golang/rename_check.go` — без смены сигнатуры на ключевом слове `func` и без
  счётчика телеметрии; место конфликта — полный путь файла; `renameExported` отказывает, если связанный метод лежит в
  пакете, который не импортирует пакет объявления; `checkMethod` отказывает переименовать метод, который `fmt`
  находит через `any` (`internal/gopls/FORK.md`).

## v0.4.0

- PHP: индекс — в общей базе пользователя `<кэш пользователя>/agent-lsp/cache.sqlite` (`internal/cachedb`), таблицы
  `php1_…`. Факты файла (объявления и места, которые их называют) адресуются хешем содержимого и сборкой (правила
  извлечения и парсер); на корень хранится только карта «путь → хеш» с размером и временем изменения. `Open`
  перечитывает только файлы с изменившимися размером или временем и разбирает только содержимое, фактов которого в
  базе нет: правка одного файла переразбирает его один, второй worktree не разбирает ничего из уже разобранного.
  Каталог `agent-lsp/php/` в кэше пользователя пакет не использует; его можно удалить.
- PHP: корень — каталог с `composer.json` или `.git`; иначе `Open` возвращает ошибку. Корень ищет программа.
- PHP: `Definition` по имени класса, интерфейса, трейта, enum, функции и константы с учётом namespace и `use`
  (`use function`, `use const`, групповые и с псевдонимом), с откатом неквалифицированной функции или константы к
  глобальной; объявления — в корне, `vendor/` и стабах. `Declaration` несёт диапазон, сигнатуру, докблок и `Origin`
  (`vendor` для `vendor/`, `std` для стабов).
- PHP: `Symbols` (`Cart`, `Cart::add`, `Shop\Cart`, `\Shop\Cart::add`, голое имя по последнему сегменту) по корню,
  `vendor/` и стабам — в этом порядке, и `Outline`.
  `References` — и для классов, функций и констант.
- PHP: стандартная библиотека — JetBrains phpstorm-stubs v2026.2 (Apache-2.0), встроенные в бинарник из `php/stubs`
  (`php/stubs/STUBS.md`); +8.8 МБ к бинарнику. Стабы разбираются один раз на базу; файл стаба, на который указывает
  ответ, записывается в `<кэш пользователя>/agent-lsp/php-stubs/<хеш>/`.
- PHP: синтаксис PHP 8.3–8.4 (типизированные константы классов, property hooks) парсер не разбирает. Файл с ним
  индексируется по дереву, которое восстановил парсер: класса с таким синтаксисом в индексе нет, его методы
  записываются как функции; ошибки разбора — в диагностике.
- Новые виды `agentlsp.Kind`: `KindClass`, `KindInterface`, `KindTrait`, `KindEnum`, `KindClassConst`.
- `internal/cachedb` включает внешние ключи: строки, которые ссылаются на удалённую чисткой строку
  (`ON DELETE CASCADE`), удаляются вместе с ней.

## v0.3.0

- Go: `References` — использования символа в пакетах корня и отдельным списком `Implementations` типы и методы,
  которые реализуют интерфейсный тип или метод интерфейса; для конкретного типа или метода список пуст. Объявление не
  использование; вопрос с использования и с объявления даёт один ответ. `Unresolved` пуст: gopls разрешает каждый
  идентификатор по типам. Неверная позиция — та же ошибка, что у `Definition`.
- Go: пакеты корня загружаются под linux, darwin и windows (представление gopls на каждую, загрузки идут разом), какую
  бы `GOOS` ни задавало окружение. `References` объединяет ответы платформ: место в файле только под windows или darwin
  попадает в ответ, место, которое видят несколько платформ, — один раз; места идут по файлам, строкам и колонкам.
  `Definition` отвечает и в файле под одну из платформ, `Symbols` ищет в пакетах всех трёх. `.go`-файл, который не
  собирает ни одна из них, — ошибка `Definition` и `References`.
- Форк gopls: `typesinternal.UsedIdent` и проверка метода интерфейса — свои тела вместо `go:linkname` в
  `golang.org/x/tools/go/types/typeutil`, которых в зависимой версии x/tools нет (`internal/gopls/FORK.md`).
- Форк gopls: представление не строит в фоне индекс кэша модулей для автодополнения (`modindex`): процесс не разбирает
  файлы кэша модулей и не создаёт каталог `<кэш пользователя>/goimports`.

## v0.2.0

- Пакет `golang`: Go-код корня — модуля или `go.work`. `Definition` (в том числе в стандартную библиотеку и
  зависимости), `Symbols` по имени с квалификатором (`pkg.Func`, `Type.Method`, `pkg.Type.Method`, путь пакета) и по
  голому имени, `Outline` файла. `References` и `Rename` возвращают `ErrNotSupported`.
- Ответы Go даёт форк внутренних пакетов gopls v0.23.0 (BSD-3) в `internal/gopls`, без протокола LSP; правки
  перечислены в `internal/gopls/FORK.md`.
- Кэш Go — общая база `<кэш пользователя>/agent-lsp/cache.sqlite` (`internal/cachedb`) для всех корней: кэш gopls и
  загрузки пакетов. `go list` повторяется только при изменении `go.mod`, `go.sum`, `go.work`, состава `.go`-файлов или
  их импортов, платформы, флагов сборки или настроек `go env -w`; строки без использования 14 дней удаляются попутно;
  файл, который не база SQLite или повреждение которого видно при открытии базы (схема, чистка), удаляется и
  создаётся заново. Порча, найденная позже (загрузка пакетов, запись кэша gopls), — ошибка вызова с путём файла базы:
  файл удаляет человек, следующий вызов индексирует заново. Процессы открывают и пересоздают базу по очереди под
  блокировкой файла `cache.sqlite.lock`. PHP хранит индекс в своём файле на корень.
- Корень, открытый через символическую ссылку, обходится через неё; пути в ответах идут через корень в том виде, в
  каком его получил `Open`.
- `Close` можно вызвать повторно: второй вызов ничего не делает.
- `Definition` возвращает `[]agentlsp.Declaration`: место имени, диапазон объявления, сигнатуру, докблок и
  происхождение (`Origin`: корень, std, module, vendor). PHP заполняет место имени.
- `agentlsp.Symbol` — имя, вид (`agentlsp.Kind`: `KindFunc`, `KindMethod`, `KindType`, `KindField`, `KindVar`,
  `KindConst`), контейнер и объявление.
- Зависимости: `golang.org/x/tools`, `golang.org/x/mod`, `golang.org/x/sync`.

## v0.1.0

- Модуль `github.com/hakastein/agent-lsp` — Go-библиотека: программа импортирует её и спрашивает напрямую, без
  LSP-сервера, демона и подпроцессов.
- API общий для языков: корневой пакет `agentlsp` — позиции, места, ответы и `ErrNotSupported`; пакет `php` —
  `Open(root, logf)` и индекс с методами `Definition`, `References`, `Rename`, `Symbols`, `Outline`, `Close`.
- PHP: `Definition` и `References` методов с известным классом получателя (правила — ADR 0001). `References`
  отдаёт использования в `Uses`; `Rename`, `Symbols` и `Outline` возвращают `ErrNotSupported`.
- Позиция — абсолютный путь, строка и колонка в байтах, обе с 1.
- SQLite — `modernc.org/sqlite` через `database/sql`, без CGO. Индекс лежит в
  `<кэш пользователя>/agent-lsp/php/index-v3-<парсер>/`.
- Платформы — linux, darwin и windows.
- Программа, которая импортирует agent-lsp, повторяет в своём `go.mod` строку `replace` парсера PHP.
